# Mushroom body: Netmorph parameter optimization

This log tracks the steps and results of preparing a batch of Netmorph
reservoir growths for the mushroom-body-style circuit (PN → KC → MBON, plus
APL). The batch provides scored samples from which Marianna builds a
predictive model, following the approach of the autoassociative example.

Work branch: `rkoene-20261103-drosophila-labels` (based on `Drosophilla_example`).

## Approach

- **One pathway at a time.** The pathway under study is **PN → KC**. PN
  (50 cells) and MBON (34 cells) stay fixed for this first batch. Only KC
  parameters vary.
- **Parameter samples.** `NetmorphParOptim/MushroomBody_ParSpace_700_samples.xlsx`
  has 700 Latin hypercube samples, generated by `mushroombody_parameter.py`:

  | column | range |
  |---|---|
  | `days` | 19–23 |
  | `KC.shape.radius` | 200–800 |
  | `KC.shape.thickness` | 100–500 |
  | `KC.minneuronseparation` | 10–30 |
  | `dm.weight` | 0.1–1.0 |
  | `KC.pyramidal` | 16–128 |

- **Neuron model.** LIFC neurons. This is a synthetic ground truth, an
  "animal X" with mushroom-body-like architecture built from the cell types
  Netmorph has, not a model of *Drosophila* cells.

## The batch script: `gen_autonm_labels.py`

This is adapted from `src/models/autoassociative/gen_autonm_labels.py`.

### Columns become Netmorph directives

Each spreadsheet column is appended to `nesvbp-mushroombody` as
`<column>=<value>;`. Netmorph uses the last value given, so these override the
values in the file. `COLUMN_ALIASES` maps columns whose names differ from the
directive they set:

| column | directive |
|---|---|
| `dm.weight` | `all_axons.axondm.dm_weight` |

New columns, such as `PN.pyramidal` or `MBON.pyramidal`, work without code
changes.

The script refuses to run if a column sets a direction model parameter for a
label that the model file does not define. A column like that would silently
have no effect. `-ignorecols <col> ...` excludes columns.

### Scoring

The script gets each region's neurons (`PN`, `KC`, `MBON`, `APL`) from NES. It
does not assume neuron IDs come in contiguous blocks. For each pathway it builds
a pre × post matrix of summed AMPA peak conductance (g_sum_peak), as in
`drosophila_resevoir.py`. The labeled spreadsheet and `ExpsDB.json` get these
columns for each pathway (`PNKC`, `KCMBON`):

| column | meaning |
|---|---|
| `usable_<p>` | pairs with g_sum_peak ≥ threshold (`usable_connections_method2()`, the score used in the autoassociative example) |
| `drivable_<p>` | postsynaptic neurons whose k strongest inputs together reach 27.44 nS |
| `pairs_<p>` | possible pairs (pre count × post count), so that fractions can be computed |
| `connected_<p>` | pairs with any AMPA connection |
| `maxg_<p>` | the largest g_sum_peak of any pair |
| `n_PN`, `n_KC`, `n_MBON` | population sizes reported by NES |

Failed runs get -1. Rows that have not been run yet are left empty.

27.44 nS is the combined peak conductance with which one presynaptic LIFC cell
can drive its target, derived in `autoassociative/LIFtest.py`. Each synapse
contributes 0.98 nS, so 27.44 nS corresponds to 28 synapses.

| pathway | inputs meant to drive a target (k) | usable-pair threshold |
|---|---|---|
| PN → KC | 7 (`-PNKCInputs`) | 27.44 / 7 = 3.92 nS (4 synapses) |
| KC → MBON | 1 (`-KCMBONInputs`) | 27.44 nS |

`-PNKCGPeakSumTarget` and `-KCMBONGPeakSumTarget` override the thresholds.
Comparisons with the thresholds use a 0.01% tolerance, because float32 synapse
sums can land just below an exact multiple.

### Running

Run from this directory:

```
# From a laptop, against the VM (as Run.sh -R does):
./gen_autonm_labels.py -Host pve.braingenix.org -from_sample 0 -to_sample 4

# On the VM itself (64 CPUs), full batch:
./gen_autonm_labels.py -fitcpus -deleteresident
```

Notes on these commands:

- `-to_sample` is exclusive, so `-from_sample 0 -to_sample 4` runs samples 0–3.
- `-fitcpus` sizes the number of parallel runs to the CPUs of the machine the
  script runs on. That only helps when the script runs on the VM. From a laptop,
  use `-batchlimit N`.
- `batchinfo_completed.json` lets an interrupted batch resume. Move or delete it
  to start fresh.
- Results go to `NetmorphParOptim/MushroomBody_ParSpace_700_samples-labeled-RS<seed>.xlsx`.

## Smoke tests (samples 0–3)

Each smoke test ran from a laptop against the VM, used random seed 20240628,
and took about 30 minutes. The time is set by the slowest single-threaded
Netmorph run.

### 1 and 2: without axon guidance, threshold 27.44 for both pathways

The state and logs are in `smoke1/` and `smoke2/` (untracked).

- Almost nothing was usable: 0–2 usable pairs per pathway out of 800–6000.
- Connections were plentiful (16–33% of pairs connected), but weak. The median
  connected pair had 2 synapses, and the 99th percentile had 12–18. Reach was
  not the bottleneck; the number of synapses per pair was.

### 3: with axon guidance and `dm.weight`, PN → KC at 7 inputs

| sample | dm.weight | KCs | drivable KCs | usable PN→KC pairs / pairs | connected | median / 99% g (nS) |
|---|---|---|---|---|---|---|
| 0 | 0.2 | 64 | 29 (45%) | 375 / 3200 | 869 | 2.9 / 44 |
| 1 | 0.7 | 120 | 57 (48%) | 1087 / 6000 | 2003 | 3.9 / 178 |
| 2 | 0.2 | 24 | 20 (83%) | 435 / 1200 | 699 | 4.9 / 56 |
| 3 | 0.9 | 120 | 97 (81%) | 2427 / 6000 | 3962 | 4.9 / 194 |

- KC → MBON: 19–475 usable pairs, and 10–28 of the 34 MBONs are drivable by a
  single KC.
- The scores now vary meaningfully across samples, so the batch can give the
  predictive model something to learn from.
- Guidance raises the number of synapses per pair a lot, especially at high
  `dm.weight`. The strongest pairs reach 100–550 nS, which is hundreds of
  synapses. That may be unrealistic (axons wrapping around dendrites), so it
  should be checked visually once the visualization tool is available. If
  needed, synapse weights can be set to 0 to reduce the effective number.
- Guidance barely changed Netmorph run time.

## Full batch (all 700 samples, 2026-11-10)

Ran on the VM with `./gen_autonm_labels.py -fitcpus -deleteresident` (64 runs
in parallel, against the NES/API servers already running there), random seed
20240628.

- **Run time:** about 12 h 45 min (10:07 to 22:53), roughly 55 samples per
  hour. That is twice the expected 6 hours, probably because each Netmorph run
  is slower with 64 running at once.
- **700 completed, 0 failed.** `resource_checks.json` recorded no failed
  requests, and no score is -1 or empty.
- **Results:**
  `NetmorphParOptim/MushroomBody_ParSpace_700_samples-labeled-RS20240628.xlsx`
  (force-added to git despite the `*-labeled-*` ignore rule, so the data is
  kept) and `ExpsDB.json`.

Spread across samples:

| score | min | 10% | median | 90% | max |
|---|---|---|---|---|---|
| `usable_PNKC` | 31 | 226 | 615 | 1761 | 3582 |
| `usable_PNKC` / `pairs_PNKC` | 0.03 | 0.09 | 0.19 | 0.45 | 0.71 |
| `drivable_PNKC` | 4 | 11 | 33 | 70 | 114 |
| `drivable_PNKC` / `n_KC` | 0.13 | 0.26 | 0.48 | 0.84 | 1.00 |
| `n_KC` | 16 | 24 | 72 | 120 | 128 |
| `usable_KCMBON` | 0 | 20 | 124 | 344 | 573 |
| `drivable_KCMBON` (of 34) | 0 | 6 | 16 | 25 | 34 |
| `maxg_PNKC` (nS) | 18 | 68 | 225 | 588 | 1574 |

- Every sample has some usable and drivable PN → KC connectivity. None scored
  0.
- **`KC.shape.radius` dominates.** Its Spearman correlation with both PN → KC
  fractions is -0.91. The other parameters correlate weakly (|ρ| ≤ 0.21):
  `days` +0.17 to +0.21, `KC.shape.thickness` -0.16, `KC.pyramidal` -0.14 to
  -0.19. `dm.weight` and `KC.minneuronseparation` show essentially none (|ρ| ≤
  0.03). This does not match the smoke tests, where high `dm.weight` samples
  looked stronger. In those four samples `dm.weight` likely varied together
  with other parameters. The weak effect of `dm.weight` is worth a closer look,
  and the reproducibility noise also needs to be kept in mind.
- The strongest single PN → KC pairs reach up to 1574 nS (about 1600
  synapses), which reinforces the axon-wrapping concern from smoke test 3.
