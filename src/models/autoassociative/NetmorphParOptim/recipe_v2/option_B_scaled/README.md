## Short answer
Yes, inhibition acquires a measurable functional role in the scaled model, in two of the three controls, replicated on the second seed network. The role is narrow and costs recall if pushed too far. At natural-bound strength (R3 as is, x1) it had none, as before.
- (a) Spurious-activity suppression: with background Pyr->Pyr raised to 4-6x the 0.15 nS cap, the silenced (GABA=0) network runs away (hundreds of spurious non-member Pyr spikes, never ends); the scaled-inhibition network stays clean and recalls. Threshold shift on S1: runaway onset c ~0.6 (silenced and x1; 0.5 is an edge) -> 0.85 (s3,g5), 1.0 (s5,g5), between 1.0 and 1.5 (s7,g5, last clean point 1.0). Seed629: onset 0.55 (silenced and x1) -> 0.7 (s3,g5, last clean 0.65), 0.75 (s5,g5, last clean 0.7), 1.0 (s7,g5, last clean 0.9).
- (c) Cross-talk between overlapping memories: at 37.5 % overlap (3 of 8 cells shared) cueing memory A also fires 2 (S1) or 2-3 (seed629) non-shared cells of memory B in the silenced and x1 networks; scaled inhibition (s3,g5 / s5,g5) removes it on S1 (2 -> 0, all c tested) and removes/reduces it on seed629 (2 -> 0 at c 0.15; 3 -> 1 at c 0.45).
- (b) Burst end: only weak. Extra member re-firing drops (S1 c 0.3: 44 -> 34-37 Pyr spikes in the 4-memory ripple, silenced 44); last spike earlier in overlap designs (S1 k=2: 8.1 -> 4.6 ms, k=3: 13.7 -> 4.5 ms; seed629 k=3: 12.5 -> 9.0-9.7 ms, 22.0 -> 10.7-12.5 ms at c 0.45) and in one ripple memory at c 0.55 (12.73 -> 3.9-6.9 ms). With a clean 8-spike volley and c <= 0.45 the burst ends at ~4.5 ms in all conditions (nothing to shorten); inhibition makes the last member spike slightly later at c 0.15 (4.5 -> 4.7-5.0 ms).
- Usable window: s3-s5 on Pyr->Int with GABA x5 keeps full recall (4-cell completes 16/16, 3-cell cues 0 false completions, 4-memory ripple 12/16/20 ms + shuffled all succeed, on both networks). s7 starts to veto cues (S1 ripple 12 ms memory 4 completes 2/4 at c<=0.2; seed629 memory 3 completes 3/4 in the 12 ms ripple), s10+ vetoes recall (6-13/16 completions) with or without background. Extension to x20 Pyr->Int / x10 GABA was run once at two points (c 0.15 and 0.75, S1): recall destroyed (2/16 and 3/16 completions), no benefit.

## Method
- patch_B.py: copy of the model file, edit receptor records (72-byte LIFCReceptorBase; gaba_patch/gabafile.py, inhibition_timing/recmap.py to identify Pyr->Int AMPA and all GABA). Pyr->Int AMPA: PeakConductance x s, Weight 1.0; GABA (Int->Pyr and Int->Int): Weight x min(g,5), PeakConductance x g/min(g,5). Rise/decay untouched (0.5/10 ms GABA). ModelLoad readback is checked in every run (`loaded_ok`: GABA weight 0.2*min(g,5), AMPA/NMDA 0.2 and Pyr->Int 1.0, all programmed g_peak_sums identical to the design; 0 mismatches).
- runB.py: R3 recipe (cue 16.5 nS, loop cap 8 nS, Pyr->Int programmed to s x g_peak at weight 1) with a uniform background: weight 1.0, per-pair conductance = min(g_peak, c) nS (so c is the actual per-pair Pyr->Pyr conductance; R3's c=0.15 is the same up to pairs with g<0.75 nS). Ripple = 4 memories at 12 ms spacing, dt 1 ms; single = 4-cell cue plus two 3-cell cues per memory. SG control = identical patched model with every GABA pair weight set to 0 via SetPrePostStrength (readback gaba_nonzero_after = 0) so interneurons still fire.
- Overlap designs (ovl_design.py, ovl_build.py): memories M0 and M1 share k=0,1,2,3 non-cue cells (0/12.5/25/37.5 %), M2/M3 disjoint; all cue->noncue pairs >= 4.5 nS as R3. design.build assumes disjoint memories, so ovl_build takes per-memory interior weights with max over memories (loop cap of 8 nS applies per memory). One random design per k and network (groups_ovl*_k*.json). Cross-talk = distinct non-shared members of the other overlapping memory (and any other memory) that fire in the 450 ms window after a cue (ovl_analyze.py; shared cells excluded).
- emu_scan.py/scan1-4: numpy emulator (fable_design_S1/net.py) used only to choose the grid. It did NOT predict NES (emulator runaway at c~1.85 for weight 0.5; NES at c~0.5-0.6 at weight 1.0), so none of its numbers are reported as results.

## Criteria
"Measurable difference vs GABA-silenced identical network in at least one of (a),(b),(c), replicated on second seed": met for (a) and (c) (both networks), partially for (b). Condition for it: Pyr->Int and Int->Pyr strength beyond the natural per-pair bound (s>=3 on Pyr->Int, 4.6x natural; GABA x5 = 2x natural unitary per pair). At R3 as is (x1/x1) there is no effect except the c=0.5 edge on S1 (see note).

## Honest limits and inference
- Everything here is reduced-model scaling: Pyr->Int per pair 4.6-7.7x natural in the working window (R3 weight 1 was already 1.54x), 15-31x in the s10/s20 points; GABA 2x natural per pair (x5 weight) with 10 ms decay (3x natural). It is a statement about this 96-Pyr/48-Int network with ~12 pyramidal inputs per interneuron, not a natural-bound result. Natural totals are still not reached (see equivalents).
- The background level where inhibition matters (c 0.6-1.0 nS per pair, 4-7x the 0.15 nS natural cap, on every pair of 9,000 Pyr->Pyr pairs) is itself non-natural. The test shows the scaled inhibition raises the runaway threshold by ~1.5-2x; it does not show natural-strength inhibition does.
- Inference (not tested): the effect works through the extra Pyr->Int->Pyr feedback once interneurons are driven by the runaway/overlap spread, not through the 8-cell volley itself (in clean recall the interneurons fire ~17-36 spikes over the four full cues for s3-s5, and the burst still ends at ~4.5-5 ms). I did not isolate Int->Pyr vs Int->Int; no IS (Pyr->Int zeroed) control was run in this round.
- Overlap: one random design per k per network, 8-cell memories so k=3 is 37.5 %; the 10 % level is not representable (1 cell = 12.5 %). Cross-talk exists only at k=3 (two or three cells), so (c) rests on a small count (2-3 cells, 1 cued memory) but is identical across c and across the two networks (different designs). No cross-talk was seen with 3-cell cues or in k<=2.
- c=0.5 on S1 is a chaotic edge (non-monotonic), and the emulator did not predict NES. NES is deterministic here (Seed 0, repeated conditions reproduce), but each condition is one run; no repeats over simulation seeds.
- Recall window is narrow: s7 already costs recall on one memory, s10 destroys it (inhibition vetoes cues; the same mechanism that stops runaway).
- Orphan sims: a mistake of mine (two batches overlapped for ~1 min, 4 concurrent sims for under 2 minutes; no crash) caused 28 failed jobs that left resident sims 80-111 (not deleted by the failed scripts); I deleted them via DeleteResidentByID (ids 80-85, 87-92, 94-100, 102-106, 108-111) after verifying they were mine by id ordering and timing (they sit between my logged ids, none are other users'), and fixed runB.py to delete on ModelLoad failure. The invalid jobs were rerun; the data tables use only completed runs with `loaded_ok`.
