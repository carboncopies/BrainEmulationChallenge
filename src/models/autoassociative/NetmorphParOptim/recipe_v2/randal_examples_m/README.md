## (a) Collapse to the disc centre / attractor settings
- **Nothing says "natural arborization" in any Netmorph/BEC doc** (grep `natural arbor|arborization`: only source-comment hits in synapse.cc, network.cc etc., and the BEC challenge .tex; none defines it for steering). "Collapse to the centre" is also not described anywhere. So whether collapse is what Randal means: **not answered**.
- What the examples do (this is the settings answer):
  - NM/examples/nesvbp/nesvbp-autoassociative:129-151 and BEC/autoassociative/nesvbp-autoassociative:129-151 (same steering block in both, Randal; the NM file has 10 pyramidal, 0 interneurons, radius 50, the BEC file 16 + 16, radius 100): `all_axons.direction_model=segment_history_tension; all_axons.dm_label=axondm; all_axons.axondm.dm_weight=0.2; all_axons.axondm.direction_model=cell_attraction; detailed_chemical_factors=true; soma_attraction_weight=0.0; In.attractedto=NGF_A; In.attractors=NGF_A;`. In the BEC file one region `In` (disc radius 100, thickness 20; 16 pyramidal + 16 interneuron, lines 60-70) is both attractor and attracted: **every axon, pyramidal or interneuron, is pulled by the same factor towards all cells of the same disc.** No interneuron-specific line (the interneuron elongation lines are commented out, lines 72-76).
  - The comment above those lines (NM/.../nesvbp-autoassociative:131-137) says the attraction goes "to the centroid location of an attractive other region". The code does **not** do that when `detailed_chemical_factors=true`: NM/axon_direction_model.cc:655-693 sums one pull per attractor soma (inverse-square, `d/|d|^3`, :645-646, times `soma_attraction_weight`, :669) and per attractor dendrite segment (:675-693, no soma weight), then `predict()` (:743-744) **normalises the sum to a unit vector and multiplies by dm_weight**. The centroid code path is `test_cell_attraction_2regions` (:731), used only when no chemical factors are specified. So "centroid" is the documented default-mode intent; the example config uses the other mode. (My reading of the code; the whole of `predict_direction` sits inside `#ifdef TESTING_SIMPLE_ATTRACTION` (:709), which NM/CMakeLists.txt:210,249 define.)
  - `soma_attraction_weight=0.0` is in every example that sets chemical factors (autoassociative:143, xor:212, mushroombody:164). With it 0 the soma branch is skipped (:716 requires `>0.0`), so attraction there acts only through dendrite points (:723-727).
  - **Steering interneurons differently exists, in the XOR examples:** BEC/xor_scnm/nesvbp-xor:214-229 gives each cell group its own factor (`Interneuron0.attractors=NGF_I0; Interneuron0.attractedto=NGF_P1; Pyramidal0.attractedto=NGF_POut; ...`). That is the pattern for "interneurons target specific pyramidal groups". Also `neuron_specific_attraction_switch=true` / `single_attractor_per_growthcone=true` (nesvbp-xor-res-sep-targets:185-187, dm_weight 0.4) and `attraction_moderation_base` (:186, commented out) are used in the separate-targets examples; not in autoassociative.
  - Mushroom body (BEC/Drosophilla_model/nesvbp-mushroombody:155-170, Randal 20240628): `all_axons.axondm` lines are **commented out**; steering rests on chemical factors only, incl. interneuron `APL.attractors/attractedto`.
- Verdict: no definition of "natural"; example settings found (above). Question for Randal stays open.

## (b) Interneuron axons with their own dm.weight
- **No example sets dm.weight per cell type.** Every example sets only `all_axons.axondm.dm_weight` (grep over NM/examples and BEC): values 0.05 (nesvbp), 0.2 (autoassociative, xor, three, simple, simpledense, attraction), 0.4 (xor-res-sep-targets, xor-res-moredendrites), 0.5 (denser, synapses), **2.0 (nesvbp-denser2)**. `all_dendrites.dendritedm.dm_weight=1` appears in two files. Parsing is generic by label (NM/axon_direction_model.cc:238, `label+"dm_weight"`), and the label chain is per set, so a per-type set (`all_interneuron_axons`) is syntactically possible; nothing in the repos uses it (the interneuron lines in the examples are commented out).
- **Where 0.1-1.0 comes from:** Randal's `BEC/autoassociative/NetmorphParOptim/ParameterSpace_700_samples.xlsx` (commit 2026-04-08): 700 samples, columns `days 20-25, pyramidal 16-128, interneuron 16-128, minneuronseparation 10-15, shape.radius 100-200, shape.thickness 20-50, dm.weight 0.1-1.0` (read with stdlib zipfile; max 0.99999...). It is **one global value**, no per-type column; `gen_autonm_labels.py:334-337` (Randal, 2026-06-05) reads a single `dm.weight` (default 0.5) into `all_axons.axondm.dm_weight`. That is the source behind our bio_ranges.json hard limit (which says "as relayed 2026-11-09"; I found the same numbers in the xlsx).
- Verdict: nothing says interneurons may or may not carry their own weight; the only evidence is that the tooling exposes a single global dm.weight. Also note `nesvbp-denser2` uses 2.0, outside 0.1-1.0, so the sample range is a search range of that study, not a documented limit of the code.

What follows (for the E4 question, stated as comparison, not as Randal's statement):
- Everywhere in the examples, GABA per **pair** is of the order **8-80 nS**; our grown E4 pairs get **0.57-0.82 nS** (0.16 nS x 3.6-5.1 synapses, from `gaba_check_l`), a factor of about 10 to 100 lower. The Netmorph-derived default per synapse (0.8 nS) is the same per-receptor-unit constant LIFtest.py uses, but LIFtest.py multiplies it by 20 "supersynapses" per pair and every interneuron contacts every cell; a Netmorph-grown pair gets only the number of synapses the geometry produces.
- Timing: the full-adder/LIFtest designs **put the interneuron spike a fixed 3 ms after the principal input**, i.e. inside the window that `gaba_check_l` found (veto only if the interneuron fires within about 3 ms of the cue). The Netmorph-grown E4 recall relies on recruited interneurons, whose first spike came at 5.3-9.5 ms. LIFtest.py's autoassociative recall also does not drive interneurons, so I found **no example in which inhibition vetoes cue completion by recruited feedback**; no result log for that is in the repo. I did not find "feedback inhibition design" text (no document says what strength or latency recall inhibition should have).
- Not re-run: full_adder_lifc.py (pass table taken from validation_results.md), LIFtest.py.
