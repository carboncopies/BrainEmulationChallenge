# math_tests PHASE 2: PREREGISTRATION of simulation batch S1 (written 2026-11-25 before any phase-2 simulation; not edited; deviations in DEVIATIONS.md as D1...)

## What is tested and why these designs
Phase-1 ranking by delivery (see PHASE1_RESULTS.md; C2 exact packing still running when this was written, its output cannot feed an A17 design so it does not change the selection) put these five methods first among those that can become a concrete network design for the dense 17-cell assembly A17 (alloc_b.json) of s66666 and s77777, plus one design that tests the main negative result:
- **BASE**: the stored recipe that worked: member AMPA matrix scaled to rho 16.5, then members with in-assembly input < mean - 1 SD boosted to the mean in-assembly input, rho held (neuron_reset_ahp step E rule P, built in the runner by `run_nr5.make_arm`, not re-implemented).
- **W13** (C6, a-priori worst-case slack rule): rank members by the worst-case 13-subset input (sum of the 13 smallest in-weights, the input a member gets from a 75% cue); boost members below mean - 1 SD of that quantity up to the mean; rho held at 16.5. Differs from BASE by using the worst-case input instead of total input.
- **LPS** (C1/C7, per-cell LP max-slack): per member LP (cutting planes) maximising slack s of "every 13-subset of the others gives >= T_eff and every 4-subset <= T_eff - 1" with T_eff = 13.6 nS (calibrated from the stored data: 75% completes at rho 15.8-17), then the minimal-total-weight solution at slack min(s*, 1); weights inside [0.1 G, min(G, 6.86)]. Left at its own rho (15.3-15.4, no rescale up).
- **CASC** (C3, cascade-minimal rho): random local search (3000 moves) for the matrix with the smallest rho such that 98% of 400 random 13-of-17 cues complete by threshold cascade at T_eff 13.6; rho 16.4 (s66666) and 16.5 (s77777).
- **RN** (C10): the member matrix found by a (1+10) search in the reduced model rn.py on a training cue set (150 generations), start = BASE-like design; rho 16.15 / 16.88. Held-out reduced-model result on its own held-out set was worse than its start (75%: 0.75 / 0.67 vs 1.0), so this design is a test of whether rn.py search transfers, not a favourite.
- **E20** (C3 negative-result test): cascade-minimal design for 9-of-17 (50%) cues, rho 20.4 / 20.6. The method predicts that 50% cues complete only together with ignition (no window): this design is a deliberate test of that claim, not a candidate to pass.
Everything is within the stated limits: per-pair <= 6.86 nS (largest 3.6-5.9 nS), weight in [0.1, 1.0] of G, NMDA nominal r <= 1.0, GABA x1. **Input cap 49.5 nS is NOT met by any design**: members over 49.5 nS (including the grown hub cell, s77777 cell 3, 57.2 nS floor input) are listed per design in `p2_designs.json` (W13/LPS/CASC/RN: 0-2 members over; BASE as stored: s66666 1 member, s77777 2-3). Reported, not relaxed beyond the stored recipe's own status.

## Simulation protocol (identical for all designs; neuron_reset_ahp step E conventions)
Models s66666 and s77777 (E4 growths), A17 assemblies, original neurons (no neuron patch), r 1.0, GABA x1, single-spike cue spread over 1.5 ms (run_pl.cue_times_lin), 9,000 ms spacing, STDP off, dt 0.1 ms, patched build. **New cue set** (key `M2025-s<seed>`, generated by run_pl.make_events, saved in `p2_cues_s*.json`): 27 events = 1 full, 6 x 75% (13/17), 6 x 50% (9/17), 6 x 25% (4/17), 4 x single cell, 4 x unrelated (8 non-member cells); shuffled order; the same cue set for every design of a model. Designs are programmed through the patched API (AMPA via BatchSetPrePostStrength, then NMDA 0.56... = r x AMPA capped as in the stored runs: same `plist_for`/`X.program` path as run_pl/run_nr5; only the member block of the arm matrix is replaced). 6 designs x 2 models = 12 simulations, one per process, deleted in `finally`.

## Measures and criteria (as in the task; scorer = neuron_reset_ahp/analyze_d.summ logic; contamination excluded)
- PASS75: 75% cues complete >= 5/6 AND every completing event ends within 100 ms (last Pyr spike <= 100 ms after the cue) AND 25% / single-cell / unrelated cues recruit nothing AND no non-member spikes (events with non-member spikes = 0).
- PASS_T (the unsolved target): PASS75 AND 50% cues complete >= 3/6.
- Reported: full cue, completion counts per class, median/max last spike, stops100, spikes per member, non-member events, members over 49.5 nS (max input), max pair, input of the weakest members, rho (as designed and as achieved by the programming read-back).
- Reduced-model predictions (rn.py, written to `p2_rn_pred.json` before any sim): BASE 75% 6/6 and 6/6; W13, CASC, RN 5/6 on both models; LPS 3/6 (s66666), 4/6 (s77777); 50% 0/6 for all except E20 (6/6 and 4/6, not ending: 0/6 and 2/6 end within 100 ms), 25% recruit E20 1/6.
