## 0. Short answer
1. **The API cannot set GABA or NMDA.** `SetPrePostStrength`, `BatchSetPrePostStrength`, `SetAllStrength` all end in one function, `LIFCNeuron::UpdatePrePostStrength` (`Simulator/LIFCompartmental/LIFCNeuron.cpp:543-559`): the first AMPA record of the pair gets `weight = G / g_peak_sum`, and every other record from that presynaptic cell, NMDA and GABA included, gets weight 0 (READ).
2. **Routes that really set GABA/NMDA** are (a) creation-time parameters (`LIFCReceptor/Create`, `NetmorphLIFCReceptor/Create`) for hand-built models, (b) editing a copy of the saved model file and `Simulation/LoadModel` (what `gaba_vm`/`gaba_patch` did), and (c) the hard-coded Netmorph build constants (needs a rebuild). Nothing edits a receptor of a built model through the API (READ).
3. **Minimal NES patch** is about 40 lines in 6 files (section 3): an optional `Neurotransmitter` argument on the three routes, applied per (pre, post, type) group. It is back-compatible and goes to a branch for Randal's review.
4. **NMDA on** needs either the file route or the patch, because API-programming AMPA zeroes NMDA on that pair. Per-synapse build ratio NMDA/AMPA = 0.55/0.98 = 0.56. Details and caveats in section 5.

## 1. Where GABA and NMDA come from and what one "pair" is (READ)
- Receptor types: `enum NeurotransmitterType { AMPA = 0, GABA = 1, NMDA = 2 }` (`Simulator/Structs/Receptor.h:30-34`). **Not the same numbers as the connectome output**: `GetConnectome` reports type 1 = AMPA, 2 = GABA, 3 = NMDA (`LIFCNeuron.cpp:517-521`). The saved-model file stores the enum values (0/1/2) (`gaba_patch/gabafile.py` docstring; checked on a real file by us).
- A receptor record is `LIFCReceptorBase` (`Receptor.h:88-112`): `ReversalPotential_mV, PSPRise_ms, PSPDecay_ms, PeakConductance_nS, Weight, OnsetDelay_ms, voltage_gated, STDP_Method, STDP_A_pos, STDP_A_neg, STDP_Tau_pos, STDP_Tau_neg, STDP_Shift, Neurotransmitter` (+ ID, ShapeID, Source/DestinationCompartmentID).
- **Netmorph build constants** (`Netmorph/NetmorphManagerThread.cpp`): AMPA rise 0.5 / decay 3.0 ms, E 0, Hebbian STDP (`:337-345`); NMDA rise 2 / decay 100 ms, E 0, `voltage_gated = true`, no STDP (`:346-358`); GABA rise 0.5 / decay 10 ms, E -70, no STDP (`:359-363`). Per-synapse peak = quantity x unit: AMPA 49 x 0.02 = **0.98 nS**, NMDA 11 x 0.05 = **0.55 nS**, GABA 10 x 0.08 = **0.80 nS** (`:366-376`; `Simulator/Structs/Simulation.cpp:302-308`). **Every** Netmorph receptor gets `C.Weight = 0.2` (`:457`).
- **Abstracted mode (default, `Simulation.h:118`)** merges receptors by (presynaptic cell, postsynaptic cell, **type**): `FindLIFCReceptorPairing` (`LIFCNeuron.cpp:395-404`) matches source and type, then `AddToAbstractedFunctional` (`Structs/Neuron.cpp:74-80`) sums peaks and takes the peak-weighted mean weight. So one pair has up to three independent groups, AMPA, NMDA, GABA, each with `g_peak_sum` and `weight`; the instantaneous conductance of a group is `min(g_peak_sum, weight x g_peak_sum x kernel)` (`Neuron.cpp:149-155`); NMDA is multiplied by `B_NMDA(Vm)` (`:143-147`, 1 mM Mg, gamma 0.33, beta 0.062). In non-abstracted mode every receptor is its own group (`Simulation.cpp:290-296`).
  - Correction to my earlier note: `gaba_vm/API_NEEDS.md` says "per pre/post pair" (GABA_LEVERS.md already had the correct (pre, post, NT) key); the correct key is pre / post / **type**. This matters for the patch: AMPA, NMDA and GABA of one pair are already separate objects, so per-type setting needs no new storage.
- Per-pair strength is therefore `weight x g_peak_sum` per type, and `g_peak_sum` = (number of synapses grown for that pair) x per-synapse peak. The API can change `weight` only; `g_peak_sum` is fixed at build or load.

## 4. Model-file editing versus the API path
- **Equivalence (READ in our results):** file-programmed AMPA weights and API-programmed ones gave identical spikes in the V0 check, 512 spikes, max difference 0.0005 ms, Vm difference 0.00002 mV (`gaba_vm/README.md` row V0), so the file route reproduces the API's per-pair AMPA behaviour. This is what the "fable-knobs" runs used, and it is the same result as in this section's code reading: after `LoadModel` every record is re-aggregated per (pre, post, type) by `AddLIFCReceptor`, with weight = sum(w_i g_i) / sum(g_i) (`Neuron.cpp:77-79`), the same object the API edits.
- **Where the file route is strictly more capable:** it can set GABA and NMDA weights, peak conductances, kinetics and reversal per record, and keep NMDA while AMPA is programmed. The API cannot do any of these (section 2).
- **Where the API route is better:** live edits between events without a reload; no dependence on the binary layout; works on any model in memory.
- **Risks of the file route:** offsets are found by pattern, record size 72 bytes (`LIFCReceptorBase`), neurons record 188 bytes; a changed struct or compiler breaks it; edits must be on copies; the receptor-array order and IDs must be preserved (`Simulation.cpp:675`, `:717-718`, `:883-884` as quoted in `GABA_LEVERS.md`, READ there).
- **Granularity:** the loader sums receptors per (pre, post, type) again, so editing single synapses of a pair inside the file only changes the peak-weighted mean; the effective strength is still one number per group.

## 5. What NMDA needs to re-run recall with NMDA on
Established (READ in code today and in our own runs): every earlier recall used the API to program pairs, so on every programmed pair NMDA weight was zeroed (`LIFCNeuron.cpp:551-553`; connectome NMDA nonzero 0 after `apply_pairs`, `gaba_vm/API_NEEDS.md` row 3). The build default is NMDA weight 0.2 on every grown NMDA group, with per-synapse peak 0.55 nS against AMPA 0.98 nS, so NMDA/AMPA = 0.56 at equal weight; NMDA is voltage gated, rise 2 ms, decay 100 ms, E 0, no STDP (section 1).
What has to be set:
1. **Do not use `SetAllStrength(0)` or per-pair API programming unmodified**: they zero NMDA (and GABA) everywhere they touch. Either (a) program through the model file (as `gaba_vm` did), (b) use the patched API of section 3, or (c) program AMPA through the API and then re-set NMDA afterwards, which only works with the patch.
2. **Choose the rule and state it:** NMDA conductance per programmed pair = r x AMPA target G, i.e. NMDA `weight = r x G_AMPA / g_peak_sum_NMDA`, capped at weight 1 (and the simulator caps conductance at `g_peak_sum_NMDA`, `Neuron.cpp:152`). Our `gaba_vm` runs used r = 0.56 (build ratio) and r = 1.0 (`gaba_vm/PREREGISTRATION.md` line 13); 120 NMDA groups hit the cap (`gaba_vm/README.md` line 93).
3. **Unprogrammed grown pairs:** after programming, pairs outside the memories keep whatever weights the model/file has. State whether they keep AMPA 0.2 and NMDA 0.2 (grown default) or are zeroed. In our earlier runs AMPA was programmed to the design values and the rest cleared; the NMDA state of non-memory pairs has to be checked in the connectome before running (READ it with `GetConnectome`, type 3).
4. **NMDA per pair has its own synapse count:** the grown NMDA group of a pair has `g_peak_sum` = n_N x 0.55 nS, where n_N differs from the AMPA count n_A (S1: 51,782 NMDA vs 58,462 AMPA synapses, `gaba_patch/README.md`). Same-conductance NMDA is therefore not always reachable.
5. **Voltage gate (INFERRED from the formula `B_NMDA(V) = 1/(1 + 0.33 exp(-0.062 V))`, `Neuron.cpp:143-147`):** at V = -70 mV (principal resting potential in the build, `NetmorphManagerThread.cpp:594`) B = 0.038; at -55 mV 0.091; at -50 mV 0.120; at -40 mV 0.203; at 0 mV 0.75. So at the nS values quoted above NMDA contributes only a few percent at rest, and the threshold model (`ovlib.py`, summed AMPA conductance of fired cells) does not include NMDA at all. NMDA matters after the first spikes, through the 100 ms decay, which is what produced the runaways in `gaba_vm` (r = 0.56: 1,124-1,422 late spikes per double-cue event with GABA silenced; r = 1.0 with x1 GABA not contained; `gaba_vm/README.md` lines 9, 54-55). So the earlier "feasibility" counts (threshold model, NMDA off) are not evidence about NMDA-on recall; a sim is needed, with GABA at the level you want to compare (silenced, x1, x5).
6. **Also set explicitly (not defaults):** `SetSTDP(False)` for recall (STDP changes AMPA weights only, `Neuron.cpp` `STDP_Update`); the abstracted-mode flag as in the build (default true).
7. **Verification before the sim:** read back `GetConnectome` for every programmed pair: type 1 weight x GPeakSum = AMPA target, type 3 weight x GPeakSum = r x AMPA target (or the cap), type 2 unchanged. The V0-style check (file vs API) applies to AMPA only.
