# DEVIATIONS / addenda (lp_weights). PREREGISTRATION.md is not edited; everything that changes it is written here with the time.

## D1 (2026-11-22, after PREREGISTRATION.md was written, BEFORE any solver run): algebraic identity found while writing the solver
In the preregistered threshold model, constraint (i) (4 cue cells fire a target: sum of the four pair conductances >= T = 16.5 nS) together with constraint (ii) (any 3 of them must not: sum of any three <= 12.375 nS) forces EACH cue->non-cue pair to be >= T - 12.375 = 4.125 nS, which is exactly the R3 rule (every cue->non-cue pair >= 4.125 nS). So for a single memory the LP cannot find anything the R3 rule misses: the candidate set is the same and the minimal-L1 solution is x = 4.125 nS on every cue->non-cue pair (also the most uniform). Consequences, stated before seeing any result:
- Predictions P1 and P2 (LP count > R3 count for single and disjoint memories, 1.2-2.5 times) were written without this identity and I now expect them to MISS (the LP count should be equal to the R3 disjoint count up to packer differences). I leave them in the preregistration and score them as written.
- P5 (at least 50% of raised pairs on the 6.86 nS cap) should also MISS: the minimal solution sits on the 4.125 nS margin line, not on the cap (it is at weight w = 4.125 / G; w = 1 only where G is close to 4.125).
- Where the LP can differ from R3: (a) overlapping memories, because R3 also switched on non-cue loops (up to 8 nS) and the cue->noncue pairs of other memories; the LP keeps all other pairs at the lower bound; (b) the margin: with an unintended-input limit of 14.0 nS (sensitivity) each cue pair only needs >= 2.5 nS and the four may be unequal, which enlarges the candidate set; (c) weight lower bound 0 (sensitivity).
- Solver structure (implementation decision, not a change of constraints): during greedy packing I use the closed-form minimal solution of constraint (i) ("water-filling": x_c = min(U_c, lambda) with the sum equal to 16.5 nS, U = min(G, 6.86)) as the forced values of designed pairs and the lower bounds elsewhere, and test constraints (ii), (iii) and the input cap H on those minimal values. These minimal values satisfy a design whenever any feasible x exists for it, except that a pair used by two memories takes the larger of its two needs, which can reject sets the true LP would accept (so capacity numbers are lower bounds). The final weights of every packing are then solved by the real two-stage LP (A: min sum w; B: min max w), which must be feasible, and is also my enforcement check.

## D2 (2026-11-22, first solver attempt; the code raised ValueError before any LP was solved): the grown networks contain hub cells whose minimum allowed input already exceeds the homeostatic cap
Constraint 3 (every grown pair keeps w >= 0.1) and constraint 5 (total input per cell <= H = 49.5 nS) cannot both hold for a cell whose as-grown total input sum_i G_ij is above 495 nS. Such cells exist in 7 of the 10 E4 networks (1-2 cells each: 1021 nS in s27182, 833 in s22222, ...; in-degree up to 95 of 95 possible, i.e. connected to nearly every other pyramidal cell; median cell input is only 10-33 nS and the 90th percentile 98-177 nS). PREREGISTRATION.md section 1.5 says "declared infeasible for that H and reported". Reporting that as "primary infeasible on 7 of 10 models" would give no results, so I apply the following, in addition to reporting the finding:
- per-cell cap H_j = max(H, 0.1 x sum_i G_ij): the cap cannot be below the unavoidable minimum; those cells (the "hub cells") are listed per model, their inputs sit at the lower bound, and they can never be memory targets (raising any pair would break the cap);
- the finding itself (grown hubs with inputs 10-20 times the cap) is reported in README.md as a non-biological feature of the grown networks that the weight design cannot fix and is flagged, not hidden.
Everything else is unchanged. The preregistered statement stays valid: with w >= 0.1 enforced, the cap H = 49.5 nS is infeasible for those cells.
