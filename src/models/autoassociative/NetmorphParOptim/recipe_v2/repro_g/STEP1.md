## 3. What the NetMorph/NES source says (read-only; /home/johnjose/BrainGenix/BrainGenix-NES)
- Build uses -DPRECISE_RNG (ThirdParty/NetmorphCMake/Source/CMakeLists.txt): the generators are libcoyote::mtprng (Mersenne twister), one object per stream (X_misc, X_elongate, X_branch, X_turn, X_synapses) inside the per-run Base object (Include/Base.cpp, Netmorph::preop makes a new Base for each run). set_random_seed (global.cc:176) seeds X_misc with the seed and chains the others from it; srand(seed) is also called but libc rand() is not used by growth (grep: only in disabled code and in unrelated NES modules).
- time(NULL) seeding exists (global.hh:702 default constructor, randomseed < 1 path) but is overwritten when randomseed >= 1 is given.
- NES runs each NetMorph in its own std::thread (NetmorphRPCInterface.cpp:121 -> ExecuteNetmorphOperation), in the same process, so two or three growths execute concurrently in one process.
- One piece of shared mutable state is visible: `static float x, y;` inside normal_pdf::nfix() (global.cc:413, the Ziggurat tail sampler), plus the static tables kn/wn/fn and the flag tablesinitialized (global.cc:430-457, filled once per process). With two growth threads in nfix at once, x can be overwritten between its assignment and its return, which would change one random draw in one run and re-route the rest of that run's stream. nfix is reached only in the rare tail of normal draws (a few per cent), so a race would be rare per run but not negligible in a 30-minute growth.
- Pointer-keyed containers exist (std::set<neuron*> and std::set<fibre_segment*> in network.hh:182-191, iterated in axon_direction_model.cc:660/682, so summation order follows heap addresses), but only in the 'specified chemical factors' attraction branch; the branch used in the TESTING_SIMPLE_ATTRACTION test path walks the linked neuron list (PLL_LOOP_FORWARD), whose order is creation order. Whether our model takes the pointer-set branch was not determined (the model sets no attractor labels; the pointer-order comparison in section 2 argues against it mattering for neurons).
- No other time-, pid- or thread-dependent source of randomness was found in the growth code. getpid() (common_entry.cc:111) is only used for file naming.
Open: a data race (nfix static) is a candidate but the history has features a pure race would not give: the deviating run, when it occurs twice, gives the SAME alternative arbor (B twice for V1 s27182 and V1n30 s27182), and only V1 deviates. Both are tested in PREREGISTRATION.md.
